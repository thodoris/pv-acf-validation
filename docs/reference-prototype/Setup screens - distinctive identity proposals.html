PV-ACF · Expert Validation · Design proposal

Giving each cluster's introductory screens — and the two grounding screens — their own identity.

The eight introductory screens currently inherit the same vocabulary as the questionnaire questions: coral kicker, coral-bordered lede panel, numbered fourgap grid, italic closer. As a respondent moves from c1-setup1 through to a question and back into c2-setup1, nothing in the page tells them which cluster they are in — or that they have stopped answering and started reading orientation again. This proposal sets out a system that makes each cluster, and the grounding screens, immediately recognisable without re-writing any of the content.

01

What is making the eight screens read alike

Looking at the eight screens side by side, they share five visual moves in the same order. The pattern is good — but it is the same pattern eight times, and the same pattern the questions use, so no single screen has a distinctive shape.

A respondent's eye is currently looking for one thing first: "is this a question I have to answer, or is this reading?" The setup screens and the question screens share enough vocabulary that the answer requires reading the kicker line every time.

Five ingredients are shared across all eight screens (and most of the question screens too):

  • 01Coral kicker — same chrome accent as the question card's left bar.
  • 02Display title + tagline — same scale on every screen.
  • 03Coral-bordered lede panel — same border colour, same surface tint.
  • 04Numbered fourgap grid — same numerals, same coral colour, same rule above each.
  • 05Italic lede-panel closer — same coral-deep type.

05

Three ways to land the system — light, medium, strong

Same vocabulary; different commitment. Pick one and the eight setup screens look different by design, not by accident.

Option A · Light

Colour only

Re-colour the lede border, the fourgap numerals, and the closer per cluster. No badge, no edge accent, no measure change. The smallest change that still differentiates the four identities at a glance.

  • Coral / cobalt / sage swap on lede + grid + closer
  • Grounding loses the coral border, gets the two-rule treatment
Recommended

Option B · Medium

Colour + cluster badge + edge accent

Everything in A, plus a small "01 · PROBLEM" / "02 · FRAMEWORK" / "03 · INSTRUMENTS" badge in the title row, and a 2px coloured left edge that persists from setup screens into every question inside the cluster. Recognition is instant; the cluster colour now indexes the whole journey.

  • Cluster badge in title row of every screen in the cluster
  • 2px coloured left edge on the main column, all the way through
  • Grounding gets "— prologue —" mark and wider measure

Option C · Strong

Colour + badge + edge + question-screen accents

Everything in B, plus the question screens in each cluster pick up the cluster colour where they currently use coral — q-card left bar, kicker, selected pill, focus ring. The cluster colour becomes the dominant chrome for an entire run of screens. Strongest signal, biggest change.

  • Question screens re-colour to cluster accent (coral / cobalt / sage)
  • Right-rail affordance kickers re-colour too
  • Step progress dot in the topbar uses the cluster colour for the active cluster
06

If you pick a direction, here is what changes

Files affected

  • styles.css — add --cluster-accent, --cluster-accent-deep, --cluster-accent-tint as scoped tokens (set via [data-cluster] on the root .main).
  • styles-phase-a.css — change .lede-panel, .fourgap__num, .kicker--coral, .lede-panel--italic to read from var(--cluster-accent) instead of var(--coral).
  • shell.jsx — stamp data-cluster="problem|framework|instruments|grounding" on the root .main based on the active screen's stepId.
  • screens-problem-setup.jsx · screens-framework-setup.jsx · screens-instruments-setup.jsx · screens-orientation.jsx — add the cluster badge component to the title row; remove the hard-coded kicker--coral (it will read from the cluster token).
  • Diagrams: pass an accent prop (default coral) so FrameworkOrganisationDiagram and InstrumentReadingDiagram can be tinted cobalt/sage without code changes to their geometry.

Tokens to add

  • [data-cluster="problem"] { --cluster-accent: var(--coral); --cluster-accent-deep: var(--coral-deep); --cluster-accent-tint: var(--coral-tint); }
  • [data-cluster="framework"] { --cluster-accent: var(--cobalt); --cluster-accent-deep: var(--cobalt-deep); --cluster-accent-tint: var(--cobalt-tint); }
  • [data-cluster="instruments"] { --cluster-accent: var(--sage); --cluster-accent-deep: var(--sage-deep); --cluster-accent-tint: var(--sage-tint); }
  • [data-cluster="grounding"] { --cluster-accent: var(--ink-strong); --cluster-accent-deep: var(--ink-strong); --cluster-accent-tint: transparent; } — and the grounding layout opts out of the lede-panel left border with a modifier class.

Open questions for you

  • Should the question screens re-colour with the cluster (Option C), or stay coral? Re-colouring is the strongest signal — but coral is currently the platform's identity colour, so the change carries weight.
  • Cluster 4 (Submit / Templates) — does it want its own identity too? Saffron would complete the palette; if you intend C4 to feel like wrap-up, no accent (like grounding) is the other option.
  • Should the cluster badge sit inline with the location string in the topbar as well? The topbar already says "Problem · Introductory setup · 1 of 2" — making "01" coloured there reinforces identity without consuming column space.
  • For grounding's wider measure — 1040px is a suggestion; if it feels too generous, 960px still differentiates from the 880px cluster measure.
